**系统身份**: 你是一个资深C++后端开发工程师

**任务**: 在 `SDK/include/DataManager.hpp` 和 `SDK/src/DataManager.cpp` 中实现数据管理类，使用 SQLite 持久化保存会话和完整历史消息，并与现有 `SessionManager` 配合，实现数据持久化。

**技术要求**

- 代码逻辑清晰，结构合理，使用 C++17 语法。
- 注释完整：

  - 方法注释：说明方法功能、参数、返回值。
  - 关键代码注释：说明事务、消息顺序和并发处理等逻辑。
- 命名规范：

  - 类名使用大驼峰命名法。
  - 方法名、参数名、变量等使用小驼峰命名法。
- 声明和实现分离，头文件保存类声明，实现放入 cpp 文件。
- 复用 `Common.hpp` 中的 `Session`、`Message` 和 `ToolCall`，不要重复定义同类业务结构；优先通过数据库内部字段解决存储需求。
- 使用现有 SQLite3 和 JsonCpp 依赖，不额外引入 ORM、连接池、异步写入队列或通用数据库框架。
- 以最小改动与 `SessionManager` 衔接。
- `DataManager` 负责数据库连接、读写和事务；`SessionManager` 负责会话管理、ID 生成及消息元数据补充；`LLMProvider` 负责模型请求和工具执行。
- 使用预编译语句和参数绑定处理数据。
- 数据库连接、语句和错误信息等资源应及时释放，失败路径也不能泄漏资源；数据库文件默认保存在程序当前工作目录下的 DBFiles。
- 保证并发访问安全。初期使用单连接和一把互斥锁，保护同一连接上的完整数据库操作与事务；模型请求、工具执行和用户回调不在数据库锁内进行。
- 区分记录不存在、版本过期和数据库读写失败。查询无记录可以返回空结果，数据库失败必须明确反馈，不能伪装成空历史或保存成功；不调用 `exit()` 终止应用。
- 不做繁杂冗余的判断，不抛出无用异常，保持代码通俗易懂、可读和可复用。
- 创建数据库和表的SQL语句也要保存，写好注释放在SDK目录下。

**实现方法：**

1. 初始化数据库。根据传入路径打开或创建数据库，创建必要的数据表和索引；再次打开已有数据库时保留原有数据。初始化成功后才允许执行读写，关闭时释放连接资源。
2. 保存会话数据。使用会话表保存 `sessionId`、`userId`、`modelConfigId`、`title`、`createdAt`、`updatedAt` 和 `generation`。`sessionId` 作为主键，消息由独立消息表保存。
3. 保存完整消息。消息表关联所属会话，保存现有 `Message` 的全部字段：`messageId`、`role`、`content`、`createdAt`、`toolCallId`、`toolName`、`toolCalls`、`reasoningContent`、`protocolData`、`modelConfigId`、`modelName`、`reasoningEffort` 和 `thinkingEnabled`。`toolCalls` 可使用 JSON 文本保存，保持调用数组顺序；`arguments` 和 `protocolData` 保留原始字符串，同时保留思考签名或原生协议数据。
4. 保证消息顺序。为消息增加数据库内部的会话内顺序号，按 `Session::messages` 或本轮消息链的原顺序写入，查询时按顺序号排序。
5. 新建和更新会话。保存 `SessionManager` 已生成 ID 的新会话，包含创建时的 System 消息；更新标题、最近模型标识或时间戳时，只更新对应会话字段，不覆盖已有历史。
6. 追加历史消息。支持向已有会话追加单条消息和本轮完整消息链；追加消息、分配数据库顺序号、更新会话时间和最近模型标识放在同一个事务中，全部成功才提交，失败则回滚。保留消息原有 ID、时间、模型及思考配置；同一会话内的 `messageId` 设置唯一约束，重复提交跳过已存消息，不覆盖旧内容、不重复追加。
7. 按会话 ID 查询。通过会话 ID 获取会话及完整消息，返回能够还原为现有 `Session`、`Message` 的数据。查询不修改创建时间和最近活动时间。
8. 查询会话列表。支持按 `userId` 查询该用户的会话，按最近更新时间从新到旧排列；同一时间可用会话 ID 作稳定排序。需要完整历史时再按会话 ID 加载，避免只显示列表却读取所有会话的全部消息。
9. 更新系统提示和活动时间。支持替换、移除会话中的 System 消息，并保留其他历史；保存替换后的系统提示、消息顺序和会话更新时间，支持单独更新会话最近活动时间。
10. 清空和删除。清空某个会话的聊天记录时保留会话和 System 消息，同时递增并保存 `generation`；删除会话时删除其全部消息。会话与消息建立外键关联并启用外键约束。清空某用户全部会话时必须明确用户范围，不能误删其他用户的数据。
11. 阻止旧请求写回。消息追加时支持检查请求开始时记录的 `generation`，版本检查和数据库写入必须在同一事务中完成；会话已清空、删除或版本不匹配时，不要写入旧请求结果。
12. 与内存会话同步。由 `SessionManager` 在启用持久化时调用 `DataManager`；创建、追加、修改、清空和删除都应有对应的数据库操作，不要造成遗漏或重复。
13. 重启恢复和继续聊天。程序重新打开数据库后，能够查询用户会话，并将选定的会话按原 ID、时间、消息顺序和版本恢复到 `SessionManager`，再通过现有 `bindSession` 继续聊天，模型连接配置和可执行工具仍由调用方初始化和注册。
